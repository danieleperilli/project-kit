# Decision History

Current rules belong to [architecture](architecture.md) or [constraints](constraints.md). Use history to recover accepted intent, rationale or supersession; search for the affected ID or domain before reading records.

Record a decision only when the user accepts a durable product, technical or workflow rule. Routine edits belong in the batch's review receipt.

Create `history/decisions/YYYY-MM.md` for the first accepted decision of that month and link it below. Each entry records its stable ID, date, accepted decision, rationale, consequences, current owner and any superseded IDs. Continue the repository's existing ID sequence across files; never reuse an ID.

Preserve accepted text and original heading anchors. Corrections or reversals use a new linked decision. For an existing monolithic log, agree on adoption explicitly, retain its contents and path, and add only navigation to the new monthly records.
